# server

Imported from the `hordes-of-azeroth-server` `zhcn-063` snapshot (`930628c2c`, 2026-11-04); license GPL-2.0. This is the refactor starting point, not the final structure. See [`UPSTREAM.md`](../../../server/UPSTREAM.md) and [`provenance.yaml`](../../../provenance.yaml).

VMaNGOS 1.12.1 server (C++), with the HoA game logic in `src/game/Bonk/`.

**Status: imported.** The directory will be reshaped according to the [architecture](../../architecture/README.md).

## Planned layering

```
server/
  src/
    game/
      Bonk/          current HoA game layer (runs, loot, cards, talents, auras)
      Hoa/           refactored HoA layer (proposed)
        content/     data access generated from shared/content
        auras/       effect registry and aura lifecycle
        i18n/        message catalogue runtime
        run/         run flow
        combat/      combat hooks, triggers, procs
  sql/
    base/            VMaNGOS base schema
    content/         generated by the shared content compiler (never hand-edited)
    migrations/      structural/data fixes only
```

## Principles

- Every HoA effect is a real aura; the server keeps one copy of the effect state (see [Auras and effects](../../auras/README.md)).
- The server never hardcodes English sentences; text goes through message IDs and language tables (see [i18n](../../i18n/README.md)).
- Content data is generated by `tools/content-compiler`; `sql/content/` is a build artifact.
- Keep the kernel; refactor only proven hot spots (see [Architecture](../../architecture/README.md)).
